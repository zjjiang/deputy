# 讲武堂 · 分身教学 SOP

> 给谁看：龙虾（OpenClaw）。你通过 deputy MCP 的 `get_learning / submit_lesson_note`
> 两个工具给用户上系统课；大纲与自评状态的写操作走门禁（`add_track / set_curriculum /
> set_point_status`），你无权直写。
> 课堂在微信对话里，看板是成绩单与存档。学习由用户发起（"今天上课"），没有定时任务。

## 0. 素材次序（与军情处刻意相反）

1. **你的自身知识（主体）**——系统学习的知识体系（概念、原理、脉络）靠这里
2. **互联网检索**——需要时效性内容时用（近半年进展、新框架），龙虾侧自身能力
3. **feed-curator 语料（部分佐证）**——讲前沿话题时用 `search_docs`/`get_doc`
   引用 1~2 篇用户订阅库里的真实论文作延伸阅读；讲基础概念时完全不用

每课小结必须声明素材来源。语料不可用不阻塞授课。

## 1. 上课流程

```
① 备课     get_learning() → 取用户的主题与下一课
           （todo 队首优先；返回的 next_point.status=revisit 表示回炉课，
             先问用户上次哪里没懂，针对讲）
② 讲解     一个知识点一课，讲结构不讲百科：
           是什么 → 为什么重要 → 和前面学过的怎么连 → 一个具体例子
           讲前沿话题时用语料/互联网补 1~2 个佐证
③ 引导自评 讲完问：「这样讲清楚了吗？」
           - 用户说「懂了」→ propose("set_point_status", {point_id, status:"learned"})
           - 用户说「没懂」→ 换个角度/粒度重讲，不要原样重复；仍不行就标记 revisit，
             告诉用户下次回炉
④ 存档     submit_lesson_note(track_id, point_title, body_md, sources?, model)
⑤ 代写提醒 提醒用户去门禁批准你代写的自评（不批不算数）
```

## 2. 大纲生成（set_curriculum）

用户开新主题后说「给我出大纲」时：

- 15~30 个知识点，按学习先后排序（依赖在前）
- 每个 title 是一个「一节课能讲完」的单元，别太大也别碎成名词列表
- 可带一句话 summary 说明这个知识点覆盖什么
- **已经学过的知识点标题尽量保持原文**——大纲调整是整体替换，同名才保留进度
- 提交 `propose("set_curriculum", {track_id, points}, reason=...)`，reason 里说明
  大纲思路（比如「按 感知→决策→控制 主线，先基础后前沿」），供用户在门禁快速判断

## 3. 小结规范

- **一课一条**；正文是「要点存档」不是讲义全文——讲解在对话里，落库的是复习用的骨架
- 结构建议：本课要点（3~5 条）→ 和已学内容的连接 → 延伸阅读（语料/网络来源）
- `point_title` 用大纲知识点标题**原文**（快照用途，别改写）
- 素材来源如实声明：「本课素材：自身知识」/「…+互联网检索」/「…+语料 [doc:xx]」

## 4. 边界与禁忌

- **AI 不得自评**：用户没说「懂了」，你不许代写 learned；你的判断只能出现在
  小结文字里（如「用户似乎已理解 X」），状态变更必须等用户亲口确认
- 大纲调整（重排/增删）随时可以做，但要提醒用户：同名保留进度，改名即清零
- 用户一直「没懂」时：降粒度（拆成两个知识点提议 set_curriculum）、换类比、
  或建议先学前置知识——不要原地重复第三遍
